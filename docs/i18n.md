# Texts and languages

Every text the app and its widgets show lives in `locales/<lang>.json`
(English only for now), read through [rust-i18n](https://crates.io/crates/rust-i18n).
`locales/en.json` is the source and the fallback for missing texts.

## In code

```rust
ts!("fan.mode.auto")                          // &'static str: labels, titles
t!("fan.rpm_value", rpm = rpm_text(r))        // Cow<str>, "%{rpm} rpm" filled in
t!("unit.celsius", c = temp : {:.0})          // format the value first ("72 °C")
```

- Keys are nested by tool or screen: `fan.*`, `cleanup.*`; shared units in `unit.*`.
- The key is always a string literal (no `format!` keys), so the checks below see it.
- Same words in different places get separate keys when a translator might
  need them to differ.
- Counts: `tn!("startup.items", n = k)` reads `startup.items_one` or `startup.items_other` (both with `%{n}`).
  Languages with more forms get their own keys when they arrive.

## Checks (`cargo test`, runs in CI)

`src/i18n.rs` tests fail when:

- code uses a key that `en.json` doesn't have, or a non-literal key;
- a key in `en.json` isn't used anywhere;
- the arguments of a `t!` call differ from the text's `%{…}`;
- another locale has a key English doesn't, or different `%{…}`.

## Adding a language

Copy `en.json` to `<code>.json`, translate the values, and call
`rust_i18n::set_locale("<code>")`. Missing texts show in English.
